3 · Logged vs sensed

Did you miscount?

The rep count from the wrist, set by set, next to what was typed into Hevy. Every set gives two numbers: all the rep-like cycles, and the clean ones left after dropping cycles whose depth or speed doesn't fit the rest of the set. Those dropped cycles are nearly always the first or last in the set: unracking, a setup pull, re-racking. If the logged count falls anywhere between the two, the log and the watch agree. "Threshold range" is the all-cycles count when the detection threshold moves from 25% to 45% of a typical rep. For split squats Hevy logs reps per leg, so each of the watch's two bouts is compared with that number. Click a row to open the set.

8 · Exercise classifier

Can the watch name the exercise?

Sixteen features per set: mean wrist orientation, how much the orientation and rotation rate vary, vertical vs horizontal acceleration, range of motion and rep period. Each model is tested leave-one-set-out: it's trained on 21 sets and asked to label the 22nd, 22 times over. With only 2–4 sets per exercise from a single session, treat these numbers as a feasibility check, not a benchmark.

10 · Methods & caveats

How this was made, and what not to trust

Pipeline

  1. Data. Sensor Logger WristMotion.csv: CoreMotion user acceleration and gravity (in g), rotation rate (rad/s) and attitude at 100.5 Hz, 282,971 samples, no gaps. The recording starts at 09:38:46 UTC, which is 10:38:46 in Stockholm on CET. Hevy's 10:37 start is the same moment give or take a minute. The watch's heart-rate file holds only 11 samples from the first three minutes, so it isn't used.
  2. Vertical axis. User acceleration is projected onto −gravity, which gives "up" in the world frame without needing the yaw angle.
  3. Set windows. Located by inspecting wrist orientation and drift-free height across the whole session, in Hevy order (all 22 found). Saved in data/sets_2026-11-01.json. The automatic finder in section 9 is benchmarked against them.
  4. Reps. Each exercise counts from the signal that shows its reps most cleanly: wrist height for barbell, split squat, pulldown and lateral raise, and forearm rotation (gravity on the watch's x axis) for hammer curls and pushdowns. One rep is one turnaround inside the longest run of regularly spaced extrema; split squats keep two runs, one per leg.
  5. Velocity. Each rep is integrated from rest point to rest point with velocity forced to zero at both ends (ZUPT) and linear drift removed. The concentric phase is the velocity lobe in the lift's direction: down for pulldown and pushdown, up for everything else.
  6. Classifier. Numpy nearest-centroid and 1-NN with z-scoring fitted inside each fold, plus a scikit-learn random forest (300 trees). Rep-level models leave out whole sets so reps from the test set never leak into training.

Caveats

  1. Wrist ≠ bar. The watch measures the forearm it's strapped to. On bench and deadlift the wrist follows the bar closely. On curls, pushdowns and laterals the wrist travels an arc, so "velocity" is the vertical speed of the wrist, not of the load. Compare these numbers within an exercise, never between exercises.
  2. One arm only. Unilateral and alternating work (split squat legs, possibly alternating hammer curls) is only partly visible. A hammer-curl count shows the watch arm's reps.
  3. Absolute velocities run low. Band-limited sampling, smoothing and ZUPT all bias mean velocity a little low. Trends within a set or a ramp are more reliable than any single number.
  4. e1RM. The bench fit uses four points from one day and an assumed minimum velocity threshold. Read it as about ±10 kg. The deadlift profile is flat, so it gives no usable estimate.
  5. Small n. 22 sets and 201 reps from one person in one session. The classifier will look optimistic until it's tested on other days, other gyms and other watch fits.
  6. Turnaround ambiguity. Unracking, setup pulls and re-racking can look like reps, and fast touch-and-go reps can merge. Flagged reps are shown, not hidden.
